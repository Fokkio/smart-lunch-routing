# ครัวเที่ยงตรง — Smart Lunch Routing Demo

Angular 22 + Tailwind CSS UI demo สำหรับจัดเส้นทางและแบ่งงานไรเดอร์ส่งข้าวกล่องช่วงมื้อเที่ยง อ้างอิงข้อกำหนดจาก `Project.pdf` โดยใช้ข้อมูลจำลองและเก็บข้อมูลใน `localStorage` ของเบราว์เซอร์

Backend แยกอยู่ที่ [Fokkio/smart-lunch-routing-backend](https://github.com/Fokkio/smart-lunch-routing-backend) และติดตามงานร่วมกันผ่าน [Full Stack Team Project](https://github.com/users/Fokkio/projects/2)

สมาชิกทีมที่เพิ่งเริ่มใช้ Git ดูขั้นตอนได้จาก [คู่มือ Git และ GitHub ภาษาไทย](GIT_GUIDE_TH.md)

## ฟังก์ชันที่มีในเดโม

- จัดการลูกค้า: เพิ่ม แก้ไข ลบ ค้นหา และปักหมุดบน Leaflet + OpenStreetMap
- จัดการออเดอร์: เพิ่ม แก้ไข ลบ และจำลองออเดอร์ใหม่
- จัดกลุ่มไม่เกิน 3 ออเดอร์ต่อไรเดอร์ และเรียงจุดส่งด้วย nearest-neighbor
- คำนวณระยะทาง เวลา ค่าส่ง รายรับ ต้นทุนอาหาร และกำไร
- ตรวจเวลาส่งเทียบเส้นตาย 12:30 น.
- เสนอแผนใหม่โดยเปลี่ยนจุดเริ่มจัดกลุ่ม
- หน้าจอจัดส่งวันนี้: แผนที่เส้นทางแยกสี เวลาเสร็จ ค่าจัดส่ง และกำไร
- เปรียบเทียบแผนใหม่ก่อนเลือก โดยไม่เขียนทับแผนเดิมทันที
- หน้าไรเดอร์บนมือถือ: กรอกรหัส ดูสรุป ส่งทีละจุด และลิงก์นำทาง
- บันทึกข้อมูล dummy ในเบราว์เซอร์โดยไม่ใช้ Backend
- Angular lazy routing แยกหน้าลูกค้า ออเดอร์ จัดเส้นทาง และไรเดอร์

## เริ่มใช้งาน

```powershell
npm.cmd install
npm.cmd start
```

จากนั้นเปิด `http://localhost:4200` ระบบจะพาไปหน้าออเดอร์วันนี้

Routes หลัก:

- `/owner/customers`
- `/owner/orders`
- `/owner/delivery`
- `/rider`

## รหัสใบงานสำหรับเดโม

- `LUNCH-101`
- `LUNCH-202`
- `LUNCH-303`
- `LUNCH-404`

เจ้าของร้านต้องกด **จัดเส้นทาง** ก่อน ไรเดอร์จึงจะเปิดใบงานได้ หากเพิ่มหรือแก้ไขออเดอร์ แผนเดิมจะถูกล้างเพื่อป้องกันการใช้ใบงานที่ล้าสมัย
การแก้ข้อมูลลูกค้าจะล้างแผนเดิมด้วย เพื่อไม่ให้ใบงานยังอ้างจุดส่งเก่า

ชุดเริ่มต้นมี 26 ออเดอร์ 52 กล่อง และใช้ 9 ไรเดอร์ หากเคยเปิดเดโมมาก่อน ข้อมูลเดิมในเบราว์เซอร์จะยังอยู่และไม่ถูกเขียนทับ การเรียก `resetDemo()` จากบริการภายในหรือการล้างข้อมูลเว็บไซต์จะคืนชุดตัวอย่างใหม่ แต่จะลบข้อมูลที่แก้ไว้ในเบราว์เซอร์

## ตรวจสอบโครงการ

```powershell
npm.cmd test -- --watch=false
npm.cmd run build
node qa-smoke.mjs
```

`qa-smoke.mjs` ต้องเปิดแอปด้วย `npm.cmd start` ก่อน และใช้ Chrome ที่ติดตั้งบน Windows เพื่อลองกด flow หลักในเบราว์เซอร์จริง

## ขอบเขตที่ไม่ควรตีความเกินจริง

- เส้นทางเป็น deterministic heuristic สำหรับเดโม ไม่ใช่ผลลัพธ์ optimal ทางคณิตศาสตร์
- ระยะทางคำนวณจากพิกัดแบบเส้นตรง ไม่ใช่ระยะทางถนนหรือข้อมูลจราจรจริง
- รหัสใบงานเป็นกลไกเปิดหน้าจอเดโม ไม่ใช่ระบบ authentication สำหรับ Production
- การกดส่งสำเร็จในหน้าไรเดอร์เป็นสถานะ UI ชั่วคราว ไม่บันทึกเหตุการณ์จริง
- ช่องค้นหาสถานที่ในฟอร์มลูกค้าค้นจากข้อมูลตัวอย่างภายในเท่านั้น ไม่ใช่บริการค้นหาที่อยู่ทั่วประเทศ
- OpenStreetMap ต้องเชื่อมต่ออินเทอร์เน็ตและใช้งานตาม Tile Usage Policy
- พิกัด ชื่อ เบอร์โทร และที่อยู่ทั้งหมดเป็นข้อมูลจำลอง
