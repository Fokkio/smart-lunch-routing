# ครัวเที่ยงตรง — Smart Lunch Routing Demo

Angular 22 + Tailwind CSS สำหรับจัดเส้นทางและแบ่งงานไรเดอร์ส่งข้าวกล่องช่วงมื้อเที่ยง ข้อมูลลูกค้า ออเดอร์ แผนเส้นทาง และใบงานที่เลือกอ่านจาก backend

Backend แยกอยู่ที่ [Fokkio/smart-lunch-routing-backend](https://github.com/Fokkio/smart-lunch-routing-backend) และติดตามงานร่วมกันผ่าน [Full Stack Team Project](https://github.com/users/Fokkio/projects/2)

สมาชิกทีมที่เพิ่งเริ่มใช้ Git ดูขั้นตอนได้จาก [คู่มือ Git และ GitHub ภาษาไทย](GIT_GUIDE_TH.md)

## ฟังก์ชันที่มีในเดโม

- จัดการลูกค้า: เพิ่ม แก้ไข ลบ ค้นหา และปักหมุดบน Leaflet + OpenStreetMap
- จัดการออเดอร์: เพิ่ม แก้ไข ลบ และจำลองออเดอร์ใหม่
- จัดกลุ่มไม่เกิน 3 ออเดอร์ต่อไรเดอร์ และเรียงจุดส่งด้วย nearest-neighbor
- คำนวณระยะทาง เวลา ค่าส่ง รายรับ ต้นทุนอาหาร และกำไร
- ตรวจเวลาส่งเทียบเส้นตาย 12:30 น.
- เสนอแผนใหม่โดยเปลี่ยนจุดเริ่มจัดกลุ่ม
- หน้าจอจัดส่งวันนี้: แผนที่เส้นทางแยกสี เวลาเสร็จ ค่าจัดส่ง และกำไร
- เปรียบเทียบแผนใหม่ก่อนเลือก โดยไม่เขียนทับแผนเดิมทันที
- หน้าไรเดอร์บนมือถือ: กรอกรหัส ดูสรุป ดูเส้นทางแต่ละออเดอร์ในแอป และส่งทีละจุด
- จัดการลูกค้าและออเดอร์ผ่าน backend API; สร้างและเลือกแผนผ่าน backend API
- หน้าไรเดอร์เปิดใบงานจากแผนที่เลือกใน backend ด้วยรหัสใบงาน การกดส่งสำเร็จยังเป็นสถานะบนหน้าจอ
- Angular lazy routing แยกหน้าลูกค้า ออเดอร์ จัดเส้นทาง และไรเดอร์

## เริ่มใช้งาน

```powershell
npm.cmd install
npm.cmd start
```

จากนั้นเปิด `http://localhost:4200` ระบบจะพาไปหน้าออเดอร์วันนี้

ระหว่างพัฒนา `ng serve` ส่งคำขอ `/api` ไปที่ backend ที่ `http://localhost:3000` ผ่าน `proxy.conf.json` ต้องตั้งค่า TiDB และรัน backend แยกก่อนใช้งานหน้าที่อ่านข้อมูลจริง Production ใช้ URL ใน `src/environments/environment.production.ts`

Routes หลัก:

- `/owner/customers`
- `/owner/orders`
- `/owner/delivery`
- `/rider`

เจ้าของร้านสร้างแผนแล้วกด **เลือกแผนนี้** ก่อนนำ `jobCode` จากงานไรเดอร์ไปเปิดใบงาน ข้อมูลจริงต้องอยู่ในฐานข้อมูลที่ backend เชื่อมต่อ

## ข้อมูลในเครื่องและฐานข้อมูล

- API และฐานข้อมูลเป็นแหล่งข้อมูลหลัก ข้อมูลลูกค้า ออเดอร์ และไรเดอร์ต้องโหลดครบทั้งสามชุดก่อนหน้าเจ้าของร้านจะถือว่าเชื่อมต่อ backend สำเร็จ
- รายละเอียดแผนฉบับร่างเก็บใน `localStorage` โดยใช้ API base URL และ `routePlanId` เป็นกุญแจ เก็บสูงสุด 3 แผนและใช้ซ้ำได้ไม่เกิน 30 วินาที รายการแผนยังโหลดจาก API และล้าง cache เมื่อวันที่หรือสถานะแผนไม่ตรงกัน
- หลังสร้าง เลือก ลบแผน หรือแก้ข้อมูลลูกค้า/ออเดอร์ในเครื่องนี้ จะล้าง cache ที่เกี่ยวข้อง หน้าไรเดอร์อ่านใบงานจาก API ใหม่ทุกครั้งก่อนเริ่มงาน และการกดยืนยันส่งยังต้องสำเร็จที่ API ก่อนเลื่อนไปจุดถัดไป
- การแก้ข้อมูลจากอุปกรณ์อื่นอาจทำให้แผนฉบับร่างใน cache เก่าชั่วคราวได้สูงสุด 30 วินาที; การเปิดแผนที่เลือกแล้วอ่านจาก API ใหม่เสมอ ระบบนี้จึงไม่รับประกันข้อมูลแบบเรียลไทม์ในทุกหน้าจอ
- cache รายละเอียดแผนมีชื่อ เบอร์โทร และที่อยู่ลูกค้า ไม่ควรใช้เบราว์เซอร์ร่วมกันโดยไม่มีการป้องกันบัญชีผู้ใช้

## ตรวจสอบโครงการ

```powershell
npm.cmd test -- --watch=false
npm.cmd run build
```

การทดสอบ API กับฐานข้อมูลจริงต้องตั้งค่า backend และ TiDB แยกต่างหาก

## ขอบเขตที่ไม่ควรตีความเกินจริง

- การจัดเส้นทางใช้ OSRM ใน backend และ Haversine เป็นทางสำรอง ไม่ใช่ผลลัพธ์ optimal ทางคณิตศาสตร์
- รหัสใบงานเป็นกลไกเปิดหน้าไรเดอร์ ไม่ใช่ระบบ authentication สำหรับ Production
- หน้าแผนที่ไรเดอร์แสดงเส้นทางที่วางไว้ แต่ยังไม่มี GPS ปัจจุบันหรือคำแนะนำเลี้ยวแบบเรียลไทม์
- ช่องค้นหาสถานที่ในฟอร์มลูกค้าค้นจากรายชื่อลูกค้าในระบบเท่านั้น ไม่ใช่บริการค้นหาที่อยู่ทั่วประเทศ
- OpenStreetMap ต้องเชื่อมต่ออินเทอร์เน็ตและใช้งานตาม Tile Usage Policy
- ข้อมูลตัวอย่างที่สร้างด้วยปุ่มจำลองบันทึกใน backend และมีเครื่องหมาย `isSimulated`
